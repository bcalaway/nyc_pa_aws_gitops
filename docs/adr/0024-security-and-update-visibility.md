# ADR-0024: Security and Update Visibility for Voice and the Weekly Review (Milestone 19)

Date: 2026-10-02
Status: Proposed (2026-10-02)

## Context

Bill set up a weekly scheduled security review (a Claude agent, originally Sunday mornings, moved to Friday nights on 2026-10-02 so findings land before the weekend; emailed). Its first design could only read this repo's code and one day of container logs through `recent_logs`. It couldn't see the things that most often turn into real problems on a small platform:

- **Software that's out of date.** `dnf-automatic` applies security updates daily on the hub and NUCs, but nothing reported what it *didn't* apply, whether a reboot is pending, or that Amazon Linux 2023 never moves to a new release on its own. RouterOS, RouterBOOT, DSM and the switch firmware were only ever checked by hand. Image tags in the compose files only move when someone edits them.
- **What happened this week.** Loki keeps 30 days, but the only window into it was 24 hours of raw lines.
- **GitHub's own security alerts** (Dependabot, secret scanning, CodeQL), which need a token to read even on public repos.
- **The AWS account itself**: no GuardDuty, no Access Analyzer, no record of root sign-ins.
- **Authentik**: who's an admin, who has MFA, failed logins.
- **What the internet can actually reach.** Security-group rules and router firewall rules say what *should* be open; nothing checked from outside.

Constraints from ADR-0021/0022: home-mcp exposes named, read-only tools (no shell), holds as few credentials as possible, and anything that changes state goes through GitHub with Bill's approval. Voice answers should be short and lead with what needs Bill.

## Decision

Seven new **read-only** home-mcp tools, each backed by the narrowest source that answers it. Each degrades to a "couldn't check" line instead of failing, so the weekly review always gets a report.

| Tool | Source | New credential or permission |
|---|---|---|
| `update_status` | node-exporter textfile metrics from a host timer (`compose/*/host/update-metrics.sh`): pending updates by severity, reboot needed, AL2023 release; `node_os_info` + endoflife.date for OS end of life; snmp_exporter `versions.yml` modules (RouterOS/RouterBOOT, DSM, SG300) + MikroTik's "newest stable" feed; compose image tags on `main` vs Docker Hub/ghcr.io | none |
| `security_events` | Loki metric queries over 7–30 days, aggregates only: hub SSH + fail2ban, device login failures and config changes, home-mcp's audit log, Traefik 4xx/5xx per app and top 401/403 sources | none; Traefik's access log turned on (4xx/5xx only, JSON, headers dropped) |
| `github_security` | GitHub API: Dependabot, secret-scanning and code-scanning alerts; `main` branch rules | fine-grained PAT, alerts **read** only, the three repos (`/home-platform/github/security-read-token`, Bill creates) |
| `aws_posture` | GuardDuty findings, Access Analyzer findings, security groups open to the world beyond 80/443/51820, root and no-MFA console sign-ins (CloudTrail event history), old IAM keys | hub role gains `home-platform-hub-security-read` (List/Describe/Get only); Terraform enables GuardDuty and an account Access Analyzer |
| `authentik_audit` | Authentik API as a view-only service account (`blueprints/home-mcp-audit.yaml`): users, admins, MFA devices, events | API token generated by the hub deploy and kept in SSM (`/home-platform/authentik/home-mcp-audit-token`) |
| `exposure_check` | Weekly nmap scan from the hub of its own public IP and both sites' WAN IPs (from WireGuard peer endpoints) vs `compose/aws/host/exposure-expected.json`; live TLS expiry for every public hostname | none; a root host timer on the hub writes results to a directory home-mcp mounts read-only |
| `security_summary` | One line from each of the above, for "how's security?" | none |

Plus:
- **Dependabot version updates** (`.github/dependabot.yml`) for compose image tags, Dockerfile base images, Python requirements, Actions and Terraform providers, weekly and grouped. Chosen over Renovate because it needs no app install and shares GitHub's alert database. Postgres majors are ignored (they need a dump/restore, not a tag bump).
- **`exposure-check-now` voice job** to rescan on demand. Its `RESULT` line says nothing about findings, because voice-job output is public in this repo's Actions logs.

### Why the exposure scan runs on the hub

Scanning from GitHub's runners would be a truly independent vantage point, but this repo is public: Actions logs (and anything a job prints) are world-readable, so the results would publish the home network's open ports. On the hub, results never leave the box except through `exposure_check`. Caveats, stated in every answer: the hub reaches its own public IP through AWS's internet gateway (security-group rules apply as for any internet source, but it isn't independent), and the site routers trust the hub for WireGuard, so a port opened only to the hub would look exposed.

### Host scripts run from a root-owned copy

The hub's deployed compose dir is owned by `ec2-user`. `compose/aws/host/install.sh` copies the scripts into `/usr/local/lib/home-platform/` (root-owned) before systemd runs them as root, so nothing root executes is writable by another user. On the NUCs, Ansible installs the same `update-metrics.sh` (the two copies in `compose/aws/host/` and `compose/nuc/host/` are kept identical).

## Found while designing this (for Bill's decision, not changed here)

- **App containers can read the hub role's credentials.** The hub's IMDS hop limit is 2 (`terraform/aws/ec2.tf`) so containers like Traefik, postgres-backup and cost-exporter can use the instance role. But todo-app and hue run on the `home-platform` bridge network too, which isn't internal, so a compromise of either app could fetch the same credentials, and the hub role can read every secret in `hub_platform_deploy` (Authentik's secret key, the Postgres admin password, the voice-worker SSH key, ...). Previews are safe (their network has no route out). Options: a `DOCKER-USER` iptables rule dropping traffic to `169.254.169.254` from the `home-platform` network's subnet, allowing it only from the stack's own default network; or IMDS hop limit 1 plus static credentials for the few containers that need AWS. The first is smaller.
  - **Resolved 2026-10-02 (Bill chose the DOCKER-USER approach):** `compose/aws/host/imds-guard.sh`, installed by `host/install.sh` as `imds-guard.service` + an hourly timer. An allow-list, not a block-list: a dedicated `IMDS-GUARD` chain (jumped to from `DOCKER-USER` for 169.254.169.254) returns for the hub stack's own `<project>_default` bridge and drops every other Docker bridge, so new app networks are covered automatically. The host's own IMDS use (SSM agent, deploy scripts) doesn't pass `DOCKER-USER` and is unaffected. With `--verify` (every run) it checks from inside each container's network namespace that traefik, postgres-backup, cost-exporter and home-mcp still get a token and that every non-stack container on `home-platform` doesn't; if a platform service lost access it removes the block again (fail open rather than breaking certificate renewal) and exports `hub_imds_guard_active 0`, which `aws_posture` reports.
- **The repo publishes the sites' WAN IPs** (`docs/platform-reference.md`, and hue's compose file). They're dynamic and residential, so the practical risk is low, but it's the first thing a scanner would want.

## Consequences

- The weekly review gets live answers instead of inferring from code, and each tool works by voice too.
- One new token for Bill to create (alerts read-only) and one he never sees (Authentik audit, generated on deploy).
- GuardDuty is the only new cost; expected a few dollars a month for one instance (30-day free trial first). The paid optional plans are pinned off in Terraform.
- Traefik's access log adds a few lines per refused request to Loki. Successful requests aren't logged.
- The hub role can now list security metadata (findings, security groups, IAM users). Given the IMDS finding above, so could a compromised app container; none of it is secret, but it's a map.
- Dependabot opens a few PRs a week. Merging one to `compose/aws/**` deploys after Bill's approval, like any other change.

## Bill's steps

1. Create the fine-grained token: repositories `nyc_pa_aws_gitops`, `todo-app`, `hue`; permissions Dependabot alerts: Read, Secret scanning alerts: Read, Code scanning alerts: Read (Metadata: Read is automatic); one-year expiry. Store it: `aws ssm put-parameter --name /home-platform/github/security-read-token --type SecureString --value <token>`.
2. In each repo's Settings → Security: turn on Dependabot alerts, and Code scanning → CodeQL default setup (free on public repos). Secret scanning and push protection are already on for the platform repo; check the two app repos.
3. Approve the Terraform run, then the Platform deploy (hub and NUCs). Traefik restarts once for the access-log flags.
4. The weekly exposure scan runs Friday ~5:30pm Eastern, ahead of the 9:52pm review; "run the exposure check now" by voice gets one sooner.
